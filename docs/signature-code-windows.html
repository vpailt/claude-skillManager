1. Contexte et objectif

L'exécutable skillmanager.exe et son installeur NSIS ne sont pas signés. Windows affiche alors deux alertes : SmartScreen (« Windows a protégé votre ordinateur / Éditeur inconnu ») et le bandeau UAC « Éditeur inconnu » à l'élévation de droits.

Signer l'application avec un certificat de confiance émis par la CA interne AlmaviaCX (AD CS) supprime l'alerte UAC sur tous les postes du domaine, qui font déjà confiance à cette autorité.

iSmartScreen en interne

SmartScreen ne se déclenche en pratique que sur les fichiers marqués « venus d'Internet » (Mark-of-the-Web). Un exe copié depuis un partage réseau interne n'a souvent pas cette marque : il reste muet, signé ou non.

!Portée de cette signature

La signature n'est reconnue que sur les machines qui font confiance à la racine AlmaviaCX (postes du domaine). Sur un poste hors domaine, l'alerte reviendra — c'est le cas où Azure Trusted Signing prendrait le relais.

2. Prérequis et vérification du terrain

Avant de signer, vérifie que l'environnement réunit les conditions suivantes. Les trois premières sont généralement déjà satisfaites sur un poste du domaine.

  • Obligatoire
    Poste de build joint au domaine AlmaviaCX

    Vérifiable via PartOfDomain.

  • Obligatoire
    Une CA d'entreprise (AD CS) déclarée dans l'Active Directory
  • Obligatoire
    Racine interne AlmaviaCX dans le magasin Autorités racines de confiance

    Distribuée automatiquement aux postes du domaine par une Enterprise CA.

  • Obligatoire
    Modèle Signature de code publié + droit d'enrôlement pour ton compte

    À défaut, voir l'étape 1, Cas B.

  • Obligatoire
    Accès Internet au moment du build pour l'horodatage (RFC 3161)
  • Optionnel
    signtool (Windows SDK) accessible sur le PATH

    Requis pour la signature native Tauri ; sinon, option de repli PowerShell (section 4).

# 1. Poste sur le domaine ?  (attendu : True)
(Get-CimInstance Win32_ComputerSystem) | Select-Object Domain, PartOfDomain

# 2. CA d'entreprise déclarée dans l'AD ?  (doit lister une ou plusieurs CA)
$conf = ([ADSI]"LDAP://RootDSE").Get("configurationNamingContext")
([ADSI]"LDAP://CN=Enrollment Services,CN=Public Key Services,CN=Services,$conf").Children |
  ForEach-Object { "{0}   (serveur : {1})" -f $_.cn, $_.dNSHostName }

# 3. Racine interne AlmaviaCX déjà de confiance ?
Get-ChildItem Cert:\LocalMachine\Root, Cert:\LocalMachine\CA |
  Where-Object Subject -match "almavia" |
  Select-Object Subject, NotAfter, Thumbprint

3. Procédure de signature

  1. Obtenir le certificat de signature de code

    Cas A — le modèle est publié et tu as le droit d'enrôlement (libre-service). Depuis la console des certificats utilisateur :

    • Ouvre certmgr.msc → Personnel → Certificats → clic droit → Toutes les tâches → Demander un nouveau certificat.
    • Suivant → Stratégie d'inscription Active Directory → Suivant.
    • Coche « Signature de code » (Code Signing) → Inscription.
    • Le certificat et sa clé privée atterrissent dans Cert:\CurrentUser\My.
    ≡Cas B — le modèle n'apparaît pas

    Demande à l'IT de publier le modèle Code Signing sur la CA d'entreprise et de t'accorder les droits Lecture + Inscription. Alternative : l'IT t'émet un fichier .pfx, importé via Import-PfxCertificate -FilePath cert.pfx -CertStoreLocation Cert:\CurrentUser\My.

  2. Récupérer l'empreinte (thumbprint) du certificat
    Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert |
  Select-Object Subject, Thumbprint, NotAfter

    Note le Thumbprint (hexadécimal en majuscules, sans espaces) : c'est la clé pour l'étape suivante.

  3. Configurer la signature native dans Tauri (recommandé)

    Renseigne l'empreinte dans src-tauri/tauri.conf.json, section bundle.windows. Le build signera alors le .exe et l'installeur NSIS en une seule passe.

    "windows": {
  "webviewInstallMode": { "type": "embedBootstrapper" },
  "certificateThumbprint": "TON_THUMBPRINT_SANS_ESPACES",
  "digestAlgorithm": "sha256",
  "timestampUrl": "http://timestamp.digicert.com"
}
    !signtool requis

    La signature native s'appuie sur signtool (Windows SDK). Vérifie sa présence avec Get-Command signtool. Comme build.ps1 charge déjà l'environnement VS2022, il est souvent sur le PATH. Sinon, utilise l'option de repli (section 4).

    iHorodatage

    Le serveur d'horodatage (DigiCert) est public et indépendant de la CA interne ; il faut juste un accès Internet au build. Sans lui, la signature devient invalide dès l'expiration du certificat.

  4. Assurer la confiance sur les autres postes

    C'est ce qui fait disparaître « éditeur inconnu » partout, pas seulement sur ton poste. Une Enterprise CA publie automatiquement sa racine dans le magasin Autorités racines de confiance de tous les postes du domaine (via l'AD).

    Si la vérification n°3 de la section 2 a trouvé la racine présente, il n'y a rien de plus à faire : chaque poste du domaine affichera « AlmaviaCX ». En cas de doute, demande à l'IT de confirmer la distribution de la racine par GPO.

  5. Produire l'installeur signé

    Lance le build habituel : les artefacts sont signés automatiquement.

    .\build.ps1

4. Option de repli — signer sans signtool (PowerShell)

Si signtool n'est pas disponible, signe en PowerShell pur après le build. Cette commande ne dépend d'aucun SDK.

!Ne pas oublier l'installeur

Cette approche signe un seul fichier. Répète la commande sur l'installeur NSIS produit (...\target\release\bundle\nsis\*.exe).

$cert = Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert | Select-Object -First 1
Set-AuthenticodeSignature -FilePath ".\src-tauri\target\release\skillmanager.exe" `
  -Certificate $cert -HashAlgorithm SHA256 `
  -TimestampServer "http://timestamp.digicert.com"

5. Vérification

Contrôle que la signature est valide et horodatée, puis que l'alerte a disparu.

  • ✓La signature est valide et horodatée
    Get-AuthenticodeSignature ".\src-tauri\target\release\skillmanager.exe" | Format-List Status, StatusMessage, TimeStamperCertificate
    Attendu : Status = Valid ; TimeStamperCertificate non vide
  • ✓L'UAC affiche l'éditeur au lancement de l'installeur en élévation
    Attendu : « AlmaviaCX » au lieu de « Éditeur inconnu »
  • ✓Pas de Mark-of-the-Web sur la copie distribuée (SmartScreen muet)
    Get-Item .\skillmanager.exe -Stream Zone.Identifier -ErrorAction SilentlyContinue
    Attendu : Aucune sortie = pas de marque Internet

6. Dépannage

signtool introuvable pendant le build
Cause : Windows SDK non installé ou absent du PATH.
Solution : Utiliser l'option de repli PowerShell (section 4), ou installer le Windows SDK et relancer depuis un shell VS2022.
Après build, Status = NotSigned ou HashMismatch
Cause : Thumbprint incorrect (espaces, casse) ou certificat sans clé privée.
Solution : Revérifier le Thumbprint (majuscules, sans espaces) et que le certificat dans Cert:\CurrentUser\My possède bien sa clé privée.
Le modèle « Signature de code » n'apparaît pas dans certmgr.msc
Cause : Modèle non publié sur la CA ou droits d'enrôlement manquants.
Solution : Demander à l'IT de publier le modèle et d'accorder Lecture + Inscription à ton compte (Cas B).
UAC affiche encore « Éditeur inconnu » sur un autre poste
Cause : La racine AlmaviaCX n'est pas dans le magasin de confiance de ce poste (souvent un poste hors domaine).
Solution : Déployer la racine via GPO ; si le poste est hors périmètre du domaine, envisager Azure Trusted Signing.
La signature devient « invalide » après quelques mois
Cause : Signature non horodatée : elle expire avec le certificat.
Solution : Re-signer en incluant -TimestampServer (ou timestampUrl côté Tauri).

7. Annexe — Prouver le mécanisme sans l'IT (dry-run auto-signé)

Pour valider toute la chaîne (signer → faire confiance → l'UAC affiche l'éditeur) avant même d'avoir le vrai certificat interne, utilise un certificat auto-signé jetable.

✕Nettoyage obligatoire

Ne laisse jamais une racine auto-signée de confiance sur le poste. Les étapes 6 du bloc ci-dessus retirent le certificat de test des magasins après validation.

# 1. Créer un cert code-signing bidon
$cert = New-SelfSignedCertificate -Type CodeSigningCert `
          -Subject "CN=Valentin Pitel (test)" -CertStoreLocation Cert:\CurrentUser\My

# 2. Signer une COPIE de l'exe (jamais l'original)
Copy-Item .\src-tauri\target\release\skillmanager.exe .\test.exe
Set-AuthenticodeSignature -FilePath .\test.exe -Certificate $cert -HashAlgorithm SHA256

# 3. À ce stade, test.exe en élévation affiche encore "Éditeur inconnu"

# 4. Rendre le cert de confiance (admin) — SUR CE POSTE DE TEST UNIQUEMENT
Export-Certificate -Cert $cert -FilePath $env:TEMP\test.cer
Import-Certificate -FilePath $env:TEMP\test.cer -CertStoreLocation Cert:\LocalMachine\Root

# 5. Relancer test.exe → UAC affiche "Valentin Pitel (test)"

# 6. Nettoyage OBLIGATOIRE
Get-ChildItem Cert:\LocalMachine\Root | Where-Object Subject -match "Valentin Pitel \(test\)" | Remove-Item
Get-ChildItem Cert:\CurrentUser\My   | Where-Object Subject -match "Valentin Pitel \(test\)" | Remove-Item
Remove-Item .\test.exe, $env:TEMP\test.cer
